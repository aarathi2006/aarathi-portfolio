Healthcare Platform

Prototype built for a recruitment assignment

The problem: Patients struggle to navigate hospital departments and booking systems. They don't know which specialty handles shoulder pain, which doctor has availability this week, or whether an external hospital system has actually confirmed their appointment.

What I built: An AI-native, multi-tenant healthcare access platform where patients describe their concern in natural language, and an AI assistant handles discovery, availability checks, and booking end-to-end. Hospitals configure their services, doctors, and calendars through role-based dashboards.

How it works: A patient types "I need to see a doctor for my shoulder pain this week." The AI detects intent, infers the specialty (Orthopedics), discovers matching doctors across hospitals, checks real calendar availability, presents options, and books the chosen slot. Every appointment is created through a controlled capability, verified against a Mock EHR system, and only confirmed once external state is synchronized. Failed or ambiguous EHR responses create reconciliation records instead of false confirmations.

Engineering highlights: Multi-tenant isolation at every layer, concurrency-safe booking with pessimistic locks, idempotency keys to prevent duplicates, external verification before confirmation, and a full audit trail with correlation IDs threaded through the entire flow.

Ecommerce Product Recommendation

December 2024

Python · Flask · Scikit-learn · Pandas · NumPy

  • Problem: Ecommerce users get overwhelmed by huge catalogs and generic "top sellers" lists, leading to low engagement and lost sales.
  • Solution: A recommendation engine that suggests products based on content similarity and rating behaviour, delivered through a Flask web interface.
  • Approach: Cleaned a 5,000-row Walmart review sample, built TF-IDF vectors over product descriptions, computed cosine similarity for content-based filtering, and item-item Pearson correlation for collaborative filtering. Trending products use a Bayesian average to avoid one-review bias.
  • Highlights: Model evaluation with Precision@10 and RMSE, graceful cold-start fallback to trending, and a deployable Flask app with Gunicorn on Render.

Human Scream Detection & Alert System

February 2025

Python · Flask · Librosa · Twilio API · Scikit-learn

  • Problem: In emergency situations — assault, accidents, medical crises — victims can't always call for help. A system that detects distress automatically can save response time.
  • Solution: A backend that listens to live audio, classifies it as a human scream vs. ambient noise, and sends an automatic alert with GPS location to pre-registered emergency contacts.
  • Approach: Extracted MFCC features from raw audio with Librosa, trained a classifier on labelled scream and non-scream samples, and built a Flask interface that records and processes audio in real time. Twilio handles SMS alerts to contacts with the current GPS location attached.
  • Highlights: End-to-end signal-processing pipeline from raw WAV to actionable alert; API integration with Twilio for real-world messaging.

2025

Python · OpenCV · Deep Learning · MediaPipe

  • Problem: In online learning and remote work, it's hard to tell if someone is genuinely focused or just logged in. Simple presence detection isn't enough.
  • Solution: A real-time attention tracker that uses facial landmarks and eye gaze estimation to determine whether a user is focused, distracted, or away from the screen.
